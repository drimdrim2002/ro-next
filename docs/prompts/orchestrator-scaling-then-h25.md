# 오케스트레이터 — 세션 A(H23 기권 제거) → 세션 B(H25 greedy + 교환)

브랜치 `stage-04-alns`, 커밋 `58ce6fe` 이후. 이 세션은 오케스트레이터다 — 코드·문서를 직접 고치지 않고,
아래 두 작업을 **순서대로** 서브에이전트(Agent, general-purpose)로 실행하고 결과를 보고한다.

## 1. 세션 A — H23 기권 제거

Agent를 하나 띄운다. 프롬프트는 `docs/prompts/session-a-zone-quota-allocation-scaling.md`의 **본문 전체를 그대로**
전달한다(파일을 읽고 내용을 프롬프트에 넣는다 — 경로만 넘기지 않는다).

A가 끝나면:
- `git log --oneline -3`으로 A의 커밋이 실제로 있는지, `git status --short`가 깨끗한지 확인한다.
- A의 보고(커밋 해시·T45~T52 결과·실물 score 대조·설계와 달리 구현한 것)를 나에게 요약해 보여 준다.
- A가 실패했거나(테스트 실패·커밋 없음) 결정을 물어 왔으면 **B를 띄우지 말고** 나에게 묻고 멈춘다.
  내 답을 받으면 같은 에이전트에 SendMessage로 이어 보내거나, 답을 프롬프트에 담아 A를 다시 띄운다.

## 2. 세션 B — H25 greedy + 교환 (A 커밋 확인 후에만)

Agent를 하나 띄운다. 프롬프트는 `docs/prompts/session-b-h25-zone-quota-exchange.md`의 **본문 전체를 그대로** 전달한다.

B가 끝나면:
- 커밋·작업 트리를 같은 방식으로 확인한다.
- B의 §8 실측 표(①~④)와 "해당하는 결정 표 행"을 그대로 보여 준다. **H25 잔류·폐기·기권 대체의 결론은 내가 정한다** —
  B가 결론을 냈어도 그것을 실행하지 않는다.

## 규칙

- A와 B를 동시에 띄우지 않는다 — 같은 파일을 만진다.
- 에이전트 보고를 그대로 믿지 않는다: 커밋 해시·`mvn verify` 통과 여부는 직접 명령으로 확인한다
  (`mvn -o verify -q`, 실패 시 출력 첨부).
- 에이전트가 만든 변경을 오케스트레이터가 고치지 않는다. 고칠 게 있으면 해당 에이전트에 SendMessage로 돌려보낸다.
