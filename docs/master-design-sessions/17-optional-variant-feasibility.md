# 세션 17 — 선택 변형 문제의 적용 가능성 검토

## 확정 방향

- Phase 16의 목적은 MDVRP·OVRP·SDVRP를 모두 `ProblemTransformer` 추가만으로 구현한다고 미리 결론 내리는 것이 아니다. 각 변형을 현재 RPDPTW 모델에 대입해 표현 가능 범위와 불변조건 변경 범위를 검증하는 **feasibility study**로 진행한다.
- 이 세션에서 말하는 현재 RPDPTW 코어는 다음 전제를 가진다.
  - 요청 하나는 고정된 픽업 노드 하나와 배송 노드 하나로 구성된다.
  - 한 요청의 픽업과 배송은 같은 차량 경로에 정확히 한 번씩 포함되고 픽업이 배송보다 앞선다.
  - 차량마다 시작 터미널과 종료 터미널이 하나씩 고정된다.
  - 경로는 해당 차량의 시작 터미널에서 시작해 종료 터미널에서 끝난다.
  - 미배정 상태는 요청 단위 `RequestBank`의 이진 상태로 관리한다.
  - 이동 거리와 이동 시간은 입력 행렬을 정규화한 `TravelMatrix`에서 조회한다.
- 변형별 변경 수준은 다음 세 단계로 구분한다.

| 수준 | 판정 기준 | 의미 |
|---|---|---|
| 변환만으로 가능 | 기존 `ProblemInstance`, `Route`, `Solution` 및 ALNS 연산자의 의미를 바꾸지 않고 정적 데이터로 컴파일 가능 | 전용 Transformer와 결과 역변환만 추가 |
| 기존 확장 지점으로 가능 | 코어 불변조건은 유지하지만 `ScorePolicy`, `RouteConstraint`, `RoutePropagator` 또는 결과 매퍼가 추가로 필요 | ALNS 코어 변경 없이 프로필 조립으로 처리 |
| 코어 변경 필요 | 요청의 원자성, 경로의 시작·종료 구조, 해의 배정 상태 또는 연산자 상태 전이가 달라짐 | 별도 설계 승인 후 코어와 연산자를 함께 확장 |

- Phase 16 완료만으로 세 변형의 운영 구현이 승인되는 것은 아니다. 각 변형의 입력 계약, 결과 의미, 목적함수, 성능 영향을 문서화하고 go/no-go 결정을 내린 뒤 구현 Phase를 별도로 확정한다.
- 현재 문서 기준의 1차 판정은 다음과 같다.

| 변형 | 제한된 기본형 | 더 풍부한 변형 |
|---|---|---|
| MDVRP | 차량별 depot이 사전에 고정된 형태는 변환 중심으로 가능 | depot 선택·공유 자원 최적화는 코어 또는 해 전체 제약 확장 필요 |
| OVRP | 고정 출발지와 무복귀를 합성 종료 터미널로 표현하는 방식은 조건부로 가능 | 종료 위치 선택·종료지 자원·후속 운행은 코어 변경 필요 |
| SDVRP | 입력에서 미리 정한 독립 운송 단위로 쪼개는 제한적 전처리만 가능 | 솔버가 배송량과 분할 횟수를 결정하는 진정한 SDVRP는 코어 변경 필요 |

## MDVRP

### 대상 정의

Phase 16에서 우선 검토할 MDVRP 기본형은 다음과 같다.

- 물리적 depot이 둘 이상 존재한다.
- 차량은 계획 실행 전에 특정 시작 depot과 종료 depot에 소속된다.
- 각 차량은 한 번의 닫힌 경로를 운행한다.
- 고객은 특정 depot에 미리 배정될 수도 있고, 여러 depot 소속 차량 중 최적 차량에 배정될 수도 있다.
- depot별 사용 가능 차량 수는 입력에 생성된 실제 차량 수로 제한한다.

### 현재 RPDPTW 코어로 표현 가능한 범위

현재 `SolverVehicle`은 차량별 `startTerminalId`와 `endTerminalId`를 이미 가진다. 따라서 차량마다 서로 다른 depot을 사용하는 것 자체는 코어 변경 사유가 아니다. 같은 depot을 공유하는 차량도 각각 별도 터미널 노드 ID를 사용하되 동일 위치와 동일한 행렬 값을 갖도록 정규화할 수 있다.

다음 조건은 현재 모델로 표현할 수 있다.

- 차량별로 고정된 시작 depot과 종료 depot
- 시작 depot과 종료 depot이 같은 닫힌 경로
- 업무상 허용된다면 시작 depot과 종료 depot이 서로 다른 고정 경로
- depot별 고정 차량 대수와 차량별 용량·근무시간
- 고객이 특정 depot 소속 차량만 이용해야 하는 제한
- 고객이 여러 depot 소속 차량 중 하나를 선택할 수 있는 경우

고객의 depot 제한은 별도 고객사 조건문을 ALNS에 넣지 않고, Transformer가 `servableVehicles`에 컴파일한다. 제한이 없으면 여러 depot의 차량을 모두 후보로 두고 기존 ALNS가 차량과 경로를 선택하게 한다.

### Transformer만으로 처리할 부분

- 복수 depot 입력을 내부 위치 인덱스로 정규화한다.
- 각 차량의 고정 소속에 따라 시작·종료 터미널을 생성한다.
- 입력된 거리·시간 행렬에서 각 터미널과 요청 노드 간 행렬을 구성한다.
- depot 제한, zone 제한 및 차량 호환 조건을 합쳐 `servableVehicles`를 계산한다.
- depot별 차량 수 제한은 해당 depot에 소속된 `SolverVehicle`의 수로 표현한다.
- 결과 역변환 시 차량 경로에 실제 depot 식별자를 복원한다.

이 범위에서는 `NodeLayout`, 차량당 하나의 `Route`, 요청 단위 destroy/repair, `RequestBank`의 의미가 모두 유지된다.

### 기존 확장 지점으로 처리할 부분

- depot 또는 차량별 고정 사용 비용은 차량 정보와 불변 정책 배열을 참조하는 `ScorePolicy`에서 계산할 수 있다.
- depot별 고객 조합 금지처럼 한 경로 안에서만 판단 가능한 규칙은 `RouteConstraint`로 처리할 수 있다.
- depot별 영업시간은 터미널 시간창과 차량 근무창으로 정규화할 수 있다.

단, 여러 경로가 공유하는 depot 전체의 비용이나 제약은 경로별 `RouteConstraint`만으로 완전하게 판단할 수 없다.

### 코어 변경이 필요한 범위

다음 요구는 단순 MDVRP Transformer의 범위를 넘는다.

- 솔버가 차량의 소속 depot 또는 시작·종료 depot 자체를 선택하는 경우
- depot 개설·폐쇄 또는 사용 depot 수를 최적화하는 경우
- depot별 재고, 출고 물량, dock 수, 동시 출발 수, 처리량 같은 공유 자원 제약
- 한 차량을 여러 depot 사이에서 재배치하거나 계획 중 소속을 바꾸는 경우
- 경로 간 depot 처리량 균형처럼 해 전체를 동시에 봐야 하는 hard constraint
- depot 간 물량 환적 또는 중간 depot 방문을 허용하는 경우

이 경우에는 터미널이 차량의 고정 속성이 아니라 의사결정 변수가 된다. 따라서 터미널 선택 상태, 해 전체 자원 집계, 관련 move와 rollback 및 목적함수 비교를 함께 설계해야 한다.

## OVRP

### 대상 정의

Phase 16에서 우선 검토할 OVRP 기본형은 다음과 같다.

- 차량은 지정된 depot에서 출발한다.
- 마지막 실제 서비스 노드 이후 depot으로 복귀하지 않는다.
- 복귀 거리와 복귀 시간은 목적함수와 차량 자원 사용량에 포함하지 않는다.
- 차량은 계획기간 동안 한 경로에만 사용하며, 경로 종료 후 다음 경로에 재사용하지 않는다.

### 현재 RPDPTW 코어로 표현 가능한 범위

현재 경로는 종료 터미널을 반드시 가져야 하므로 종료 터미널 자체를 없애는 것은 구조 변경이다. 그러나 종료 터미널을 **물리적 depot이 아닌 합성 sink**로 정의하면 제한적 OVRP를 기존 경로 구조로 표현할 수 있다.

합성 sink는 다음 규칙을 가져야 한다.

- 모든 실제 노드에서 sink로 가는 거리와 이동시간은 0이다.
- sink의 서비스시간과 적재 변화는 0이다.
- sink는 실제 방문지나 depot 복귀로 집계하지 않는다.
- sink의 시간창은 마지막 실제 서비스 완료시각을 왜곡하지 않아야 한다.
- 빈 경로의 시작 터미널에서 sink로 가는 비용도 0이다.
- 입력 행렬의 대칭성을 가정하지 않고, sink로 들어오는 인위적 0 arc를 허용한다.

이렇게 하면 기존 전방 계산 결과의 거리와 운전시간에는 복귀 구간이 포함되지 않고, 경로는 여전히 시작·종료 터미널 불변조건을 만족한다.

### Transformer만으로 처리할 부분

- 차량별 합성 sink 노드를 만든다.
- 입력 거리·시간 행렬에 sink 행과 열을 추가하고, sink로 들어오는 arc를 OVRP 의미에 맞게 정규화한다.
- 결과에서 합성 sink를 숨기고 마지막 실제 서비스 노드를 차량의 최종 위치로 복원한다.
- 닫힌 경로 전용 depot 복귀 검사를 OVRP 입력에는 적용하지 않는다.

엄밀히 말하면 결과 역변환이 필요하므로 “Transformer 클래스 하나만 추가”하는 작업은 아니다. 다만 `ProblemInstance`, `Route`, `Solution`과 ALNS move의 의미가 유지된다면 코어 변경 없이 변환·결과 경계에서 처리할 수 있다.

### 조건부 검증 사항

합성 sink 방식을 승인하기 전에 다음 숨은 가정을 확인해야 한다.

- `TravelMatrix` 검증이 대칭 행렬이나 실제 좌표 간 이동만 허용하지 않는가
- 종료 터미널을 항상 물리적 depot으로 간주해 depot 작업시간이나 복귀 시간을 더하는 코드가 없는가
- `stopCount`, 사용 차량 판정과 결과 방문 수에서 sink가 제외되는가
- 최대 운전시간과 최대 거리가 sink까지의 0 arc를 포함해도 의도한 값과 같은가
- 차량 근무 종료 기준이 마지막 고객의 서비스 시작인지, 서비스 완료인지, 별도 종료 처리 완료인지

숨은 가정이 발견되면 각 Transformer에 예외 조건을 흩뿌리지 않고 `RouteTerminationPolicy`와 같은 명시적 종료 정책을 도입하는 소규모 코어 변경을 우선 검토한다.

### 코어 변경이 필요한 범위

다음 OVRP 요구는 합성 sink만으로 표현하지 않는다.

- 마지막 위치를 depot, 차고, 숙박지 등 허용 종료지 집합에서 선택해야 하는 경우
- 종료 위치에 따라 실제 이동 거리·시간·비용이 달라지는 경우
- 종료지별 수용량, 주차면, 충전기 같은 공유 자원 제약
- 오늘의 종료 위치가 다음 날 시작 위치를 결정하는 다일 차량 연속성
- 마지막 고객 이후 외부 차고까지의 deadhead는 비용에 포함하지만 depot 복귀로 보지는 않는 경우
- 경로 종료 차량을 같은 계획기간에 다시 투입하는 경우

이 경우 종료 터미널은 고정 sink가 아니라 의사결정 변수 또는 다음 계획 상태가 되므로 경로 표현, 시간 전파, 해 전체 자원 상태와 연산자를 확장해야 한다.

## SDVRP

### 대상 정의

진정한 SDVRP는 한 원주문의 수요를 둘 이상의 차량 또는 경로에 나누어 배송할 수 있고, 솔버가 각 방문의 배송량을 결정하는 문제로 정의한다.

```text
원주문 수요 = 각 분할 방문의 배송량 합 + 미처리 잔량
```

RPDPTW 문맥에서는 분할한 각 수량에 대해 픽업과 배송의 수량 보존 및 선행 관계도 함께 만족해야 한다.

### 현재 RPDPTW 코어로 표현 가능한 범위

현재 `Request`는 고정 수량을 가진 픽업–배송 쌍이고, 배정 상태는 `RequestBank`의 단일 비트다. 삽입과 제거도 요청 전체를 원자적으로 처리한다. 따라서 솔버가 한 요청의 일부 수량만 특정 경로에 싣는 상태는 현재 모델에 존재하지 않는다.

Transformer가 원주문을 여러 고정 청크로 미리 쪼개 각 청크를 독립 요청으로 만드는 방식은 기술적으로 가능하다. 그러나 다음 조건을 모두 만족할 때만 허용 가능한 제한 모델이다.

- 입력 또는 업무 규칙이 분할 단위를 사전에 확정한다.
- 각 청크를 독립적으로 픽업·배송해도 업무 의미가 같다.
- 청크별 서비스시간, 시간창, 차량 호환성과 미배정 페널티를 명확히 정의할 수 있다.
- 원주문 완료 여부를 결과 계층에서 청크별 결과로 다시 합산한다.

이 방식은 솔버가 최적 분할량을 결정하지 못하므로 진정한 SDVRP 구현으로 부르지 않는다. 청크 수가 많아질수록 요청·노드·삽입 후보가 급증하고, 서비스시간 또는 고정 방문비용이 청크마다 중복될 수도 있다.

### Transformer만으로 처리할 수 없는 이유

현재 코어의 다음 불변조건이 SDVRP와 충돌한다.

- 요청은 한 차량 경로에만 배정되거나 완전히 미배정된다.
- 요청당 픽업·배송 노드가 정확히 하나씩 존재한다.
- 노드의 적재 변화량은 정적 고정값이다.
- destroy/repair는 요청 전체를 삽입·제거한다.
- 미배정 페널티는 요청 전체에 대해 계산한다.
- 결과는 배정 또는 미배정의 이진 상태다.

따라서 임의의 분할량, 부분 배정 또는 경로 사이 수량 이동을 Transformer만으로 추가하면 해 검증·점수·결과가 서로 다른 의미를 갖게 된다.

### 코어 변경이 필요한 범위

진정한 SDVRP를 지원하려면 최소한 다음을 별도로 설계해야 한다.

- **도메인**: 원주문과 분할 방문 또는 운송 조각을 구분하고, 최소 분할량·분할 단위·최대 분할 횟수를 표현한다.
- **해 상태**: 요청별 잔량과 각 경로의 배정량을 저장하며, `RequestBank`를 `미처리 잔량 = 0/양수`를 표현할 수 있는 구조로 확장한다.
- **노드와 적재**: 방문별 배송량에 따라 적재 변화량을 계산한다. 무게와 부피의 분할 관계 및 정수 반올림 규칙도 정한다.
- **픽업–배송 불변조건**: 분할 조각별 픽업과 배송이 같은 차량에 있고, 픽업이 선행하며, 픽업량과 배송량이 보존되는지 검증한다.
- **연산자**: 분할량 생성, 부분 삽입, 부분 제거, 경로 간 수량 이동·병합을 지원하는 destroy/repair 및 local search move를 추가한다.
- **평가와 목적함수**: 주문당 한 번 드는 비용과 방문마다 드는 비용을 분리하고, 부분 미배정 페널티와 분할 횟수 페널티를 정의한다.
- **결과와 진단**: 원주문별 총 배정량, 차량별 분할량, 잔량, 분할 사유와 최종 상태를 제공한다.
- **성능**: 분할 후보 수의 상한과 분할량 후보 생성 전략을 두어 탐색 공간 폭증을 통제한다.

특히 무게와 부피가 동시에 있는 경우 임의 비율로 둘을 따로 나눌 수 없다. SKU·파렛트·박스처럼 실제 분할 가능한 단위를 입력 계약에서 제공하거나, 무게와 부피가 동일 비율로 분할된다는 업무 규칙이 필요하다.

## 공통 평가 기준

각 변형 feasibility study는 다음 기준을 동일하게 사용한다.

| 평가 항목 | 확인 내용 |
|---|---|
| 문제 의미 | 해당 변형의 표준 정의와 고객사 업무 의미가 일치하는가 |
| 표현 완전성 | 가능한 해를 누락하거나 불가능한 해를 허용하지 않는가 |
| 코어 불변조건 | 요청 원자성, 픽업–배송 pairing, 경로 terminal, 배정 상태가 유지되는가 |
| 입력 계약 | depot, 종료 방식, 분할 규칙과 거리·시간 행렬을 모호함 없이 받을 수 있는가 |
| 변환 가능성 | 정적 `ProblemInstance` 데이터로 컴파일할 수 있는가 |
| 확장 지점 적합성 | `ScorePolicy`, `RouteConstraint`, `RoutePropagator`만으로 책임을 격리할 수 있는가 |
| 알고리즘 영향 | 기존 destroy/repair, 초기해, 차량 수 최소화와 rollback을 그대로 쓸 수 있는가 |
| 목적함수 | 고객사별 목적함수가 필요한 측정값과 해 전체 상태를 얻을 수 있는가 |
| 결과 의미 | 내부 terminal·fragment를 외부 주문·depot·최종 위치로 손실 없이 복원할 수 있는가 |
| 성능 | 노드 수, 후보 수, 행렬 크기와 캐시 비용 증가가 허용 범위인가 |
| 회귀 안전성 | 기존 CVRPTW·RPDPTW 입력에서 해와 점수가 변하지 않는가 |
| 검증 가능성 | 독립 `SolutionVerifier`가 변형별 hard constraint를 재계산할 수 있는가 |

각 변형은 최소한 다음 판정 중 하나를 받아야 한다.

```text
GO_TRANSFORM       변환·결과 경계만 확장
GO_EXTENSION       기존 정책·제약·전파 확장 지점 사용
GO_CORE_CHANGE     승인된 코어 변경 후 구현
DEFER              입력 계약 또는 업무 규칙 미확정
NO_GO              현재 제품 범위에서 지원하지 않음
```

## Phase 산출물

Phase 16은 하나의 구현 Phase가 아니라 다음 순서의 설계 게이트로 나눈다.

### Phase 16A — 공통 feasibility study

- MDVRP·OVRP·SDVRP 각각의 정확한 문제 정의와 지원 범위
- 변형별 대표 입력 fixture와 사람이 계산한 기대 결과
- “변환만 / 기존 확장 지점 / 코어 변경” 영향도 표
- 현재 코어 불변조건과의 충돌 목록
- 입력 JSON 및 결과 JSON에 필요한 변경안
- 이동 거리·시간 행렬 정규화 규칙
- 고객사별 목적함수에 필요한 추가 `RouteMetrics` 또는 해 전체 측정값 목록
- 변형별 성능 위험과 규모 제한
- 변형별 go/no-go 결정 기록

### Phase 16B — 코어 비변경 변형 설계

16A에서 `GO_TRANSFORM` 또는 `GO_EXTENSION` 판정을 받은 범위만 대상으로 한다.

- MDVRP 고정 depot 차량 모델의 Transformer·결과 매퍼 설계
- OVRP 합성 sink 모델의 Transformer·결과 매퍼 설계
- 합성 terminal과 실제 terminal의 명시적 의미 및 검증 규칙
- 기존 초기해·ALNS·검증기의 재사용 가능성 확인
- 기존 RPDPTW 회귀 테스트와 변형별 acceptance test 명세

### Phase 16C — 코어 변경 변형 설계

16A에서 `GO_CORE_CHANGE` 판정을 받고 별도 승인을 받은 항목만 대상으로 한다.

- SDVRP 수량 상태와 원주문/분할 방문 모델의 상세 설계
- 부분 삽입·제거·병합 연산자의 상태 전이 및 rollback 설계
- 부분 미배정, 서비스시간과 분할 비용의 목적함수 계약
- 동적 depot 또는 선택 종료지가 필요할 경우 terminal 의사결정 모델 설계
- 기존 코어와의 호환 또는 별도 엔진 경계 결정

문서 작성 단계인 현재 세션에서는 위 산출물의 구현, 소스 변경 또는 성능 최적화를 수행하지 않는다.

## 비범위

다음 항목은 Phase 16의 기본 feasibility 범위에 포함하지 않는다.

- route pool 또는 MIP 기반 후처리
- depot 입지 선정과 신규 depot 개설 최적화
- depot 간 재고 이동과 환적 네트워크 최적화
- 실시간 주문 추가와 동적 재배차
- 차량이 하루에 여러 경로를 수행하는 완전한 multi-trip과 변형 문제의 결합
- 기사 숙박지, 다음 날 차량 재배치와 장기 차량 순환 최적화
- 연속량을 제한 없이 나누는 무한 정밀도 분할
- 임의의 MDVRP+OVRP+SDVRP 조합을 한 번에 지원하는 범용화
- 변형 문제를 이유로 초기 단계부터 별도 ALNS 엔진을 복제하는 방식

비범위 항목은 향후 별도 요구가 확정되면 독립적인 설계 결정과 Phase로 추가한다.

## 남은 질문

### MDVRP

1. 차량의 시작 depot과 종료 depot은 입력에서 고정되는가, 아니면 솔버가 선택해야 하는가?
2. 한 차량의 시작 depot과 종료 depot은 반드시 같아야 하는가?
3. 고객은 특정 depot에 미리 소속되는가, 아니면 호환되는 모든 depot 차량 중 하나가 선택될 수 있는가?
4. depot별로 차량 수 외에 출고 물량, 재고, dock 수, 동시 출발 수 또는 일일 처리량 제한이 있는가?
5. 목적함수에 depot 개설비, depot 사용비 또는 depot 간 물량 균형이 포함되는가?

### OVRP

6. “복귀하지 않음”은 마지막 고객에서 즉시 경로가 끝나 복귀 거리·시간이 모두 0이라는 의미인가?
7. 차량의 최종 위치는 마지막 고객으로 기록하면 되는가, 아니면 별도 차고·주차장·숙박지 중 하나로 이동해야 하는가?
8. 차량 근무시간 충족 기준은 마지막 고객의 서비스 시작, 서비스 완료, 또는 별도 종료 작업 완료 중 무엇인가?
9. 마지막 위치가 다음 날 차량의 시작 위치에 영향을 주는가, 아니면 각 계획 실행은 독립적인가?

### SDVRP

10. 분할 단위는 연속 수량인가, SKU·박스·파렛트 같은 이산 단위인가?
11. 무게와 부피는 같은 비율로 분할되는가, 아니면 품목 단위 구성으로부터 각각 계산해야 하는가?
12. 주문별 최소 분할량과 최대 분할 횟수가 있는가?
13. 서비스시간은 분할 방문마다 전부 발생하는가, 고정 준비시간과 수량 비례시간으로 나뉘는가?
14. 부분 배송 시 미배정 페널티는 잔량 비례인가, 주문이 완결되지 않으면 전액인가?
15. 실제 pickup 지점에서도 분할 수량마다 별도 상차 방문이 필요한가, 아니면 차량 출발 전에 각 차량에 분할 적재된 것으로 보는가?

### 공통

16. 세 변형은 서로 독립적으로만 지원하면 되는가, 아니면 초기 범위에서 특정 조합도 반드시 지원해야 하는가?
17. Phase 16A의 우선 검토 순서는 코어 변경이 가장 적은 고정-depot MDVRP, 합성-sink OVRP, SDVRP 순으로 진행해도 되는가?
